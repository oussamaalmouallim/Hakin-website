Chapitre 01 · Comprendre

L'architecture réelle de H MODE

H MODE n'a pas de serveur à vous. Le site est un ensemble de fichiers ; tout ce qui calcule, garde ou vérifie est chez Supabase. Toute la suite du guide découle de ce choix.

Les pièces, une par une

BackendSupabase : API REST, base PostgreSQL avec règles de droits (RLS), Auth, Storage, fonctions SQLprojet Supabase « HMODE » (Europe)en ligne

SMTP Brevo
Commandeenregistrée en base par passer_commande, puis message WhatsApp ; paiement à la livraisonSupabase + wa.meen ligne

Un échange réel : un client passe commande

  1. Le navigateur charge le site depuis Netlify, puis lit le catalogue chez Supabase : GET /rest/v1/produits?publie=eq.true.
  2. Le client valide /commande : le site appelle la fonction de la base POST /rest/v1/rpc/passer_commande avec la clé publique.
  3. La base vérifie tout elle-même : limite par visiteur (sinon HTTP 429), ville livrée, pièce publiée, prix lu en base (celui du navigateur est ignoré), coloris, taille. Puis elle enregistre la commande en une seule transaction.
  4. Le site ouvre WhatsApp avec le message prêt. La commande apparaît dans l'admin, Ventes → Commandes.
À retenir

Le navigateur n'est jamais cru sur parole. Prix, droits, limites : tout est vérifié dans la base. C'est pourquoi la clé publique peut être visible dans le site sans danger, et pourquoi la clé service_role (qui ignore les droits) n'est utilisée nulle part.

Chapitre 02 · Comprendre

Domaine, DNS, serveur, hébergement, API, base de données

Six mots qu'on confond souvent. Pour chacun : une définition, à quoi il sert, ce qu'il est chez H MODE, ce que vous avez à faire, et comment vérifier.

Nom de domaine

Définition
L'adresse lisible d'un site, comme hmode.ma. On la loue à l'année auprès d'un registrar (une société agréée pour vendre des domaines).
À quoi ça sert
Donner une adresse stable et mémorisable, indépendante de l'hébergeur. Si vous changez d'hébergeur, le domaine reste.
Chez H MODE
Aujourd'hui hmodeclothes.netlify.app, un sous-domaine prêté par Netlify. Un domaine à vous est prévu.
À faire
L'acheter (chapitre 6), puis le relier à Netlify.
Vérifier
L'adresse s'ouvre dans un navigateur, avec le cadenas.

DNS

Définition
Le DNS (Domain Name System) est l'annuaire d'Internet : il traduit hmode.ma en adresse de machine. Chaque ligne de cet annuaire est un enregistrement : A (domaine → adresse IP), CNAME (nom → autre nom), TXT (texte de preuve, pour les e-mails).
À quoi ça sert
Dire au monde « le site de hmode.ma est chez Netlify » et « les e-mails de hmode.ma partent de Brevo ».
Chez H MODE
Géré chez le registrar du domaine (ou chez Netlify si vous lui confiez le DNS).
À faire
Recopier exactement les enregistrements que Netlify et Brevo vous donnent.
Vérifier
dig hmode.ma +short dans un terminal, ou le site dnschecker.org : la valeur attendue apparaît partout.

Serveur

Définition
Un ordinateur allumé en permanence, relié à Internet, qui répond aux requêtes. Un serveur virtuel (VPS) est une part d'un gros serveur louée au mois.
À quoi ça sert
Faire tourner un programme qui doit répondre à tout moment.
Chez H MODE
Aucun serveur à vous. Ceux de Netlify et de Supabase font le travail ; vous n'avez ni système à mettre à jour, ni machine à redémarrer.
À faire
Rien. L'image Docker du projet (infra/docker/) existe pour un hébergement sur serveur, si un jour c'est utile.
Vérifier
—

Hébergement

Définition
Le service qui garde les fichiers du site et les envoie aux visiteurs, en général par un CDN (réseau de serveurs répartis dans le monde, qui servent une copie proche du visiteur).
À quoi ça sert
Rendre le site rapide et disponible, avec HTTPS.
Chez H MODE
Netlify. À chaque envoi de code sur main, il reconstruit le site et le publie.
À faire
Garder les variables d'environnement à jour (chapitre 8) et surveiller la jauge d'usage (chapitre 15).
Vérifier
https://…/version.json montre la dernière version et sa date de construction.

API

Définition
Une API (interface de programmation) est une liste d'adresses qu'un programme appelle pour lire ou écrire des données. Une API REST utilise les adresses web et les verbes HTTP (GET lire, POST envoyer). Une clé d'API identifie l'application qui appelle.
À quoi ça sert
Permettre au site, dans le navigateur, de parler à la base.
Chez H MODE
Fournie par Supabase (PostgREST) : une adresse par table et par fonction, par exemple /rest/v1/rpc/passer_commande. Pas d'API écrite à la main.
À faire
Surveiller son point de santé /rest/v1/rpc/sante (chapitre 11) et ses limites (chapitre 12).
Vérifier
L'admin, Supervision → Santé : « base : API et données » est « Opérationnel ».

Base de données

Définition
Le lieu où les données sont rangées en tables. PostgreSQL est la base utilisée par Supabase. La RLS (Row Level Security) y écrit, ligne par ligne, qui a le droit de lire ou modifier. Une migration est un fichier SQL daté qui fait évoluer la base.
À quoi ça sert
Garder produits, commandes, comptes, réglages, et les protéger.
Chez H MODE
Projet Supabase « HMODE ». 8 migrations appliquées ; une neuvième (santé, journal, 429) est prête.
À faire
Sauvegarder chaque semaine et tester la restauration (chapitre 14).
Vérifier
npx supabase migration list : les colonnes « local » et « remote » sont identiques.

Chapitre 05 · Choisir

Recommandation d'hébergement

Lancer sur Netlify Free et Supabase Free, avec un domaine .ma. Passer Supabase en Pro dès les ventes régulières : c'est la première dépense utile.

La recommandation

Maintenant : Netlify Free + Supabase Free + domaine .ma ≈ 100 à 200 DH HT par an.

Dès les premières commandes régulières, ou avant toute campagne publicitaire : Supabase Pro ≈ 244 DH par mois.

Plan B : si la jauge Netlify dépasse 70 % plusieurs mois de suite, migrer vers Cloudflare Pages (gratuit) plutôt que payer Netlify Personal.

Pourquoi

  1. Netlify est déjà en ligne et vérifié. Vraie page 404, en-têtes de sécurité, sitemap, aperçus de partage : tout a été contrôlé le 10/11. Changer d'hébergeur ne réglerait aucun problème réel et obligerait à tout retester.
  2. Le vrai risque est la base, pas le site. Sur Free, elle se met en pause après une semaine sans activité et n'a aucune sauvegarde restaurable. Le Pro règle les deux.
  3. Vercel coûte 195 DH par mois dès le premier jour (l'offre gratuite interdit la vente) sans rien apporter à un site statique.
  4. Cloudflare Pages est la bonne sortie si le trafic grossit : trafic statique non facturé. Une demi-journée pour porter les en-têtes et retester.

Chapitre 06 · Mettre en production

Acheter et configurer le nom de domaine

Un domaine se loue à l'année. On l'achète chez un registrar, puis on écrit dans son DNS où se trouve le site. Netlify crée ensuite le certificat HTTPS tout seul.

Étape 1 — Choisir et acheter le domaine

Quoi
Choisir .ma (clients marocains, confiance locale) ou .com (international). Un seul suffit au départ.
Où
.ma : un registrar agréé par l'ANRT (liste sur registre.ma). .com : Cloudflare Registrar, Namecheap, Porkbun…
Pourquoi
Une adresse à vous, que personne ne peut reprendre tant que vous la renouvelez.
Vérifier
Le domaine apparaît dans votre espace client du registrar, avec sa date d'expiration.
Erreurs
  • Regarder le prix de la 1re année seulement : lisez le prix de renouvellement.
  • Oublier le renouvellement automatique : un domaine expiré coupe le site et les e-mails.
  • Acheter le domaine au nom d'un tiers : il doit être à votre nom ou à celui de la boutique.

Étape 2 — Déclarer le domaine dans Netlify

Quoi
Netlify → votre site → Domain management → Add a domain → saisir hmode.ma, puis ajouter aussi www.hmode.ma.
Où
app.netlify.com
Pourquoi
Netlify doit savoir qu'il sert ce domaine, pour créer le certificat.
Vérifier
Netlify affiche « Awaiting External DNS » ou la liste des enregistrements à créer.

Étape 3 — Écrire les enregistrements DNS chez le registrar

Quoi
Recopier exactement les valeurs affichées par Netlify. En général :
Type    Nom     Valeur                              TTL
A       @       75.2.60.5            (adresse donnée par Netlify)   3600
CNAME   www     hmodeclothes.netlify.app.                     3600
Pourquoi
@ désigne le domaine nu (hmode.ma) ; www le sous-domaine. Le TTL est la durée pendant laquelle l'annuaire garde la réponse en mémoire.
Vérifier
dig hmode.ma +short
dig www.hmode.ma +short
Les valeurs saisies reviennent. La propagation (mise à jour de l'annuaire partout) prend de quelques minutes à 48 h.
Erreurs
  • Laisser un ancien enregistrement A ou AAAA du registrar (page de parking) : supprimez-le.
  • Ajouter un point ou un espace en trop en recopiant.
  • Changer les serveurs DNS (« nameservers ») et les enregistrements en même temps : choisissez l'un ou l'autre.

Étape 4 — Basculer l'adresse du site partout

Quoi
  1. SITE_URL = https://hmode.ma dans Netlify et GitHub, puis Netlify → Deploys → Trigger deploy.
  2. Supabase → Authentication → URL Configuration : Site URL https://hmode.ma, Redirect URLs https://hmode.ma/**.
  3. Service de surveillance externe : nouvelle adresse.
  4. Brevo : expéditeur noreply@hmode.ma, domaine authentifié (enregistrements TXT SPF et DKIM donnés par Brevo).
Pourquoi
Le sitemap, les aperçus de partage, les liens des e-mails et le robot utilisent cette adresse.
Vérifier
https://hmode.ma/sitemap.xml contient des adresses en hmode.ma ; un e-mail de confirmation ramène sur hmode.ma.
Chapitre 07 · Mettre en production

Déployer pas à pas depuis Netlify

Le site est déjà publié sur Netlify. Ce chapitre décrit le circuit complet d'une mise à jour, du code à la page en ligne, et ce qu'il reste à faire une seule fois.

Netlify relié et reconstruit le 10/11variables Netlify poséesGitHub Pages à désactiverCI à vérifier sur GitHub

Le circuit d'une mise à jour

  1. Vous modifiez le code en local et le testez (npm run lint, npm test, npm run build dans web/).
  2. Vous envoyez sur GitHub (git push), idéalement par une branche et une pull request.
  3. La CI se lance (intégration continue : types, tests, build, tests navigateur). Rouge = on corrige avant de fusionner.
  4. Netlify reconstruit à chaque nouveau commit sur main : npm run build dans web/, publication de dist/.
  5. Le robot voit la nouvelle version dans /version.json et la note dans l'admin (Supervision → Maintenance → Déploiements vus).

Une fois : désactiver GitHub Pages

Quoi
GitHub → dépôt → Settings → Pages → Unpublish site (ou Source : None).
Pourquoi
L'ancien site y est encore publié : une deuxième boutique périmée, trouvable par Google.
Vérifier
https://oussamaalmouallim.github.io/Hakin-website/ renvoie 404.

Une fois : vérifier que Netlify suit bien GitHub

Quoi
Netlify → Site configuration → Build & deploy → Continuous deployment : le dépôt Hakin-website, branche main, est lié.
Pourquoi
Le 10/11, un commit poussé n'avait pas été publié tout seul : il a fallu relancer à la main.
Vérifier
Après le prochain git push, Deploys montre un build « Production: main@… » et /version.json change.
Erreurs
Site importé par glisser-déposer : il n'est relié à rien. Utilisez Link repository.

Ce que Netlify lit tout seul (déjà dans le dépôt)

[build]
  base = "web"               # dossier du site
  command = "npm run build"  # types + build + sitemap + aperçus de partage
  publish = "dist"           # fichiers publiés

[build.environment]
  NODE_VERSION = "22"
Revenir en arrière en 30 secondes

Netlify → Deploys → un déploiement précédent qui marchait → Publish deploy. Effet immédiat, sans toucher au code. La base, elle, ne revient pas en arrière : voir chapitre 14.

Chapitre 08 · Mettre en production

Configurer le frontend, le backend et la base

Le frontend se configure par des variables ; le « backend » n'a rien à déployer : il se règle dans Supabase. La base évolue par migrations, toujours après une sauvegarde.

Les variables d'environnement

Une variable d'environnement est une valeur donnée au programme au moment du build, au lieu d'être écrite dans le code. Toute variable qui commence par VITE_ est copiée dans le site, donc publique.

VariablePubliqueOùRôle
VITE_SUPABASE_URLouiweb/.env, Netlify, GitHub (variable)adresse du projet Supabase
VITE_SUPABASE_PUBLISHABLE_KEYouiidemclé publique ; les droits restent vérifiés par la RLS
SITE_URLouiNetlify, GitHub (variable)adresse finale : sitemap, aperçus de partage, robot
ADMIN_EMAIL, ADMIN_MOT_DE_PASSE, ADMIN_CLEsecretweb/.env seulementcompte admin (npm run admin:sql)
SANTE_JETONsecretweb/.env + GitHub (secret)jeton du robot et des scripts de sauvegarde
SUPABASE_ACCESS_TOKENsecretGitHub (secret), facultatifappliquer les migrations depuis GitHub
NETLIFY_BUILD_HOOKsecretGitHub (secret), facultatifrepublier les aperçus quand le catalogue change
Jamais

Ni la clé service_role, ni un mot de passe, ni un jeton dans une variable VITE_ ou dans Netlify. Le dépôt est public : web/.env n'est jamais envoyé dans git.

Le backend : réglages Supabase

URL Configuration fait le 09/11

Quoi
Authentication → URL Configuration : Site URL = l'adresse du site ; Redirect URLs = https://…/** et http://localhost:6013/** (démo locale).
Pourquoi
Les e-mails de confirmation et de mot de passe oublié ramènent sur /connexion : sans /**, Supabase refuse ces liens.
Vérifier
Un e-mail de confirmation ramène sur le site, connexion réussie.

SMTP (Brevo) à faire

Quoi
Authentication → SMTP Settings : hôte, port, identifiant et clé SMTP donnés par Brevo (SMTP & API) ; expéditeur à votre nom.
Pourquoi
Sans SMTP à vous, Supabase n'envoie que 2 à 3 e-mails par heure, et seulement à l'équipe du projet : vos clients ne peuvent pas confirmer leur inscription.
Vérifier
Inscription avec une adresse à vous : l'e-mail arrive, expéditeur Brevo. Puis Authentication → Rate Limits : la limite d'e-mails est relevée.

La base de production : appliquer une migration

  1. Sauvegarder d'abord : npm run sauvegarde dans web/ (chapitre 14).
  2. Voir ce qui va changer, sans rien écrire (à la racine du dépôt) :
    npx supabase db push --dry-run
    La liste doit contenir seulement les migrations attendues, aujourd'hui 20261110120000_sante_et_journal.sql.
  3. Appliquer :
    npx supabase db push
  4. Vérifier :
    npx supabase migration list
    Colonnes « local » et « remote » identiques. Puis ouvrez https://<projet>.supabase.co/rest/v1/rpc/sante?apikey=<clé publique> : {"ok": true, …}.
Ce qui est déjà fait sur la base

Le 09/11 : projet relié, 4 premières migrations notées comme appliquées, 4 migrations du 08/11 poussées, sauvegarde d'avant gardée dans ~/Documents/HMODE-sauvegardes/. Votre compte admin a le rôle technique.

Chapitre 09 · Mettre en production

HTTPS, certificat SSL et sécurité

HTTPS chiffre l'échange entre le client et le site. Netlify s'en occupe ; votre travail est de vérifier qu'il est actif, et que les protections du site sont bien envoyées.

HTTPS et certificat

Définition
HTTPS est HTTP chiffré. Un certificat TLS (souvent appelé SSL) prouve au navigateur que le site est bien le vôtre. Let's Encrypt en délivre gratuitement, pour 90 jours, renouvelés automatiquement.
À quoi ça sert
Empêcher la lecture et la modification du trafic (mot de passe, adresse de livraison). Sans lui, le navigateur affiche « Non sécurisé ».
Chez H MODE
Actif sur hmodeclothes.netlify.app. Pour le domaine : créé par Netlify une fois le DNS correct.
À faire
Netlify → Domain management → HTTPS : certificat actif ; activer Force HTTPS.
Vérifier
Cadenas dans le navigateur ; http:// redirige vers https://.

Les protections déjà en place

ProtectionOùCe qu'elle bloqueVérifiée

Les quatre états

Opérationnel : le dernier contrôle a réussi, dans les temps. Dégradé : il répond mais trop lentement, ou il a échoué au moins une fois dans les 6 dernières heures. Indisponible : le dernier contrôle a échoué. Inconnu : aucun contrôle depuis 75 minutes. Jamais de vert sans contrôle réel.

Définition
Une fonction de la base, appelable en GET, qui répond {"ok": true, "base": "ok", "heure": …} après avoir lu une table.
À quoi ça sert

À faire

Vérifier
L'adresse ouverte dans un navigateur affiche "ok": true.

Créer les sondes externes

  1. Choisir le service : UptimeRobot (50 sondes, toutes les 5 min) ou Better Stack (10 sondes, toutes les 3 min), tous deux gratuits. Lisez leurs conditions : les sources se contredisent sur l'usage commercial de l'offre gratuite.

Chapitre 12 · Protéger

Limiter les requêtes et protéger les points d'entrée

La limitation des requêtes arrête les abus : fausses commandes en masse, spam d'erreurs, robots. Elle ne garantit pas à elle seule que l'API reste disponible.

limites en ligne depuis le 09/11réponse 429 testée en local429 en ligne après db push

Rate limiting

Définition
Compter les appels d'un même visiteur sur une fenêtre de temps et refuser au-delà d'un seuil. La réponse standard est HTTP 429 « Trop de requêtes », avec l'en-tête Retry-After (secondes à attendre).
À quoi ça sert
Empêcher qu'un script remplisse la base de fausses commandes ou masque les vraies erreurs.
Chez H MODE
Dans la base, fonction passer_limite, appelée par chaque écriture publique. Visiteur = empreinte hachée et salée de son adresse réseau (jamais l'adresse en clair), plus un plafond global, car l'adresse transmise peut être falsifiée.
À faire
Rien au quotidien ; ajuster une limite si de vrais clients sont bloqués.
Vérifier
Supervision → Sécurité : appels acceptés et bloqués sur 24 h.

Les limites configurées

Point d'entréePar visiteurTous visiteursPourquoi cette valeur
passer_commande5 / 60 min100 / 60 minun client passe une ou deux commandes ; le plafond arrête un envoi en masse
signaler_erreur30 / 10 min2 000 / 10 minune page qui plante en boucle ne remplit pas la base
noter_demande_whatsapp30 / 10 min3 000 / 10 minquelques conversations par visiteur
compter_visite120 / 10 min50 000 / 10 minau-delà de quelques pages par minute, c'est un robot
robot, scripts20 / 10 min60 / 10 minun passage toutes les 30 min, plus les relances
clé de l'admin5 erreurs—blocage 15 min, chaque erreur journalisée
comptes (Auth)limites de SupabaseAuthentication → Rate Limits

Ce qui se passe quand une limite est atteinte

HTTP/1.1 429 Too Many Requests
Retry-After: 600
  • Rien n'est enregistré ; le blocage, lui, est gardé (journal, onglet Sécurité).
  • Le site affiche : « Trop de commandes envoyées depuis cet appareil en peu de temps. Réessayez dans une heure, ou écrivez-nous sur WhatsApp. »
  • 10 blocages ou plus en 30 min : le robot alerte.

Modifier une limite

update public.limites set maximum = 8 where action = 'commande';
Ce que la limitation ne fait pas

Elle ne protège pas contre une surcharge massive : chaque requête refusée arrive quand même jusqu'à la base. Contre ça : le CDN de Netlify (les pages ne touchent pas la base), l'infrastructure de Supabase, le plafond global, les délais d'expiration (le robot coupe à 15 s, le site retombe sur le catalogue des fichiers et sur WhatsApp), et la surveillance pour réagir. En cas d'attaque réelle : support de Supabase, et baisse temporaire des plafonds.

Sauvegarde et restauration

Définition
Une sauvegarde est une copie des données, rangée ailleurs. La restauration la remet en place. Une empreinte SHA-256 est une signature du fichier : un seul octet changé, et elle change.
À quoi ça sert
Revenir en arrière après une erreur (suppression, migration ratée) ou une perte chez le fournisseur.
Chez H MODE
Supabase Free n'en fait aucune de restaurable : c'est vous. Sur Pro, Supabase en fait une par jour, et vos sauvegardes restent utiles (hors de chez Supabase).

Sauvegarder (chaque semaine, et avant chaque migration)

npm run sauvegarde
  • Écrit ~/Documents/HMODE-sauvegardes/<date>/ : roles.sql, schema.sql, donnees.sql, photos/ (si des photos ont été téléversées), manifeste.json (empreintes et nombre de lignes de chaque table).
  • Dossier réservé à votre compte (droits 700), hors du dépôt public : il contient les coordonnées des clients.
  • Note la sauvegarde dans l'admin si SANTE_JETON est dans web/.env (sinon : Supervision → Maintenance → Noter).

Tester la restauration (chaque mois)

npm run sauvegarde:tester
  1. Vérifie les empreintes : un fichier modifié ou manquant est refusé.
  2. Démarre un Supabase jetable (ports 553xx), sans toucher au projet en ligne ni au Supabase local habituel.
  3. Restaure rôles, structure et données en une seule transaction (méthode de la documentation Supabase).
  4. Compare le nombre de lignes de chaque table au manifeste ; vérifie les fonctions et une lecture à travers la RLS.
  5. Arrête et efface le Supabase jetable, puis note le résultat dans l'admin.

Restaurer pour de vrai (perte de données)

Chapitre 15 · Durer

Maintenance préventive et corrective

Préventive : ce qu'on fait pour que ça ne casse pas. Corrective : ce qu'on fait quand ça a cassé. Seul sur le projet, la préventive est votre meilleure assurance.

Préventive

  • Sauvegarde chaque semaine ; restauration testée chaque mois.
  • Jauge Netlify (Usage) chaque semaine : au-delà de 70 %, réagir avant la pause.
  • Dépendances : npm outdated dans web/ chaque mois ; mises à jour par petits groupes, CI verte.
  • Sécurité : npm audit chaque mois ; alertes Dependabot de GitHub.
  • Performances : npm run qualite:lighthouse ou PageSpeed Insights chaque mois ; LCP médian dans Supervision sous 2,5 s.
  • Domaine : date d'expiration et renouvellement automatique, chaque trimestre.
  • Accès : liste des admins et double authentification, chaque trimestre.

Corrective

  1. Constater : alerte, ou client qui signale.
  2. Mesurer : Supervision → Contrôler maintenant ; Journaux sur 24 h.
  3. Limiter les dégâts : retour arrière Netlify si un déploiement est en cause ; prévenir la boutique (commandes par WhatsApp).
  4. Corriger : branche, correction, CI verte, déploiement.
  5. Vérifier : robot vert, état « Opérationnel ».
  6. Noter : cause et correction dans le journal ; une ligne dans docs/projet/TODO.md si une action reste.
